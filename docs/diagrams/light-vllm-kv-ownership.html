KV cache：同一份容量，两个责任边界

初始化阶段先根据模型真实 KV 形状确定页数；运行阶段 Scheduler 只分配 page ID，PagedStepHandler 只读写对应的 K/V 张量。当前实现中 block ID 直接等于物理 page ID，但两侧保存的状态和负责的生命周期不同。

为什么要分成“逻辑分配”和“物理存储”

Scheduler 需要知道页够不够、某个请求占了哪些页、失败后归还哪些页；它不需要接触张量。PagedStepHandler 需要把 K/V 写到正确地址并运行 attention；它不应该自行决定把空闲页分给哪个请求。这样未来加入 prefix sharing 或 preemption 时，主要改变分配策略，不必改模型计算接口。

当前实现最容易误解的地方

block_id 现在直接索引物理 page，因此数值是一一对应的；“逻辑/物理”描述的是责任和状态所有权，不是说当前已经存在第二层地址翻译。以后需要共享或远程 KV 时，可以在中间增加映射。
