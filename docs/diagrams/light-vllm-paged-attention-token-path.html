Paged Attention：一个 query token 如何找到自己的 K/V 页

下面使用一个完整数字例子：block_size=4、已有 5 个 token、本轮计算 2 个 token、block_table=[7,2]。从绝对位置到物理 slot，再到因果注意力读取范围，每一步都对应当前代码中的字段和检查。

为什么 block table 必须“刚刚好”

少一页会让本轮 token 找不到写入位置；多一页会把未使用资源混进执行边界。当前实现还检查页号不越界、单请求不重复、不同活动请求不共享页。

为什么先写 K/V 再计算 attention

当前位置的因果注意力需要看到它自己的 K/V。写入后，位置 5 读取 0..5，位置 6 读取 0..6。PyTorch 参考实现逐页累计 softmax，没有用“先拼接完整历史”的假分页实现。

CUDA/Triton 如何接入

替换 PagedAttentionBackend 即可；模型继续调用相同的 AttentionContext，Scheduler、Engine 和模型分发不需要增加 CUDA 分支。
